# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1 (Foundation + Hero + Conversion Infrastructure). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Every spec entry is measurable or a WCAG-AA / Lighthouse / behavior assertion.

**Phase scope (anchor):** 4 client-side routes (`/`, `/flavors`, `/about`, `/contact`), a mobile-first Hero that converts via WhatsApp waitlist CTA, logo-only nav + theme toggle, in-app browser detect-and-nudge banner, branded 404, and the complete conversion scaffold (`src/config/cta.ts`, `<PrimaryCTA>`, `<TrustBadge>` declaration, FOUC-free dark mode, LazyMotion provider, Meta Pixel + CAPI edge function, Shopify-shaped `flavors.ts` stub, CI greps).

**Mobile-first mandate:** All specs below are declared at the **360×640 (iPhone SE / small Android) baseline** and scale up. 95% of traffic is Instagram/Facebook mobile ads. Lighthouse mobile ≥90; FMP <2s on 4G.

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** (greenfield custom; shadcn declined — brand palette is locked and shadcn presets would collide with the premium creative direction) |
| Preset | not applicable |
| Component library | **Radix UI primitives, package-by-package** (Phase 1: none installed; Phase 5 adds `@radix-ui/react-accordion` for FAQ). Headless-only; no opinionated UI library. |
| Icon library | **lucide-react@1.53.0** (tree-shaken SVG; icons used in Phase 1: `Sun`, `Moon`, `X`, `ArrowUpRight`) |
| Styling | **Tailwind CSS v4.3.3** with CSS-first `@theme` block in `src/index.css` (no JS config) + `@tailwindcss/vite` plugin |
| Font family (display) | **Satoshi** (self-hosted WOFF2 subset) with fallbacks → `"Inter", system-ui, -apple-system, "Segoe UI", sans-serif` |
| Font family (body) | **Inter** (self-hosted WOFF2 subset) with fallbacks → `system-ui, -apple-system, "Segoe UI", sans-serif` |
| Font loading | `font-display: swap`; both faces preloaded via `<link rel="preload" as="font" type="font/woff2" crossorigin>` in `index.html` |
| Utility helpers | `clsx@2.1.1` + `tailwind-merge@3.7.0` composed as `cn()` in `src/lib/cn.ts`; `class-variance-authority@0.7.1` for `<PrimaryCTA>` variants |

**Rationale for `shadcn: none`:** Project has a locked 4-color palette (`#594545 / #815B5B / #9E7676 / #FFF8EA`) and a locked typography intent (industrial display + humanist body) that shadcn's zinc/slate/stone presets would overwrite. The 4-layer architecture (Pages → Sections → UI → Primitives) already defines the component contract; shadcn registry safety gate is not applicable because no third-party components are consumed in Phase 1.

## Spacing Scale

8-point scale (strict multiples of 4). Mobile baseline unless noted.

| Token | Value | Usage |
|-------|-------|-------|
| xs  | 4px  | Icon-to-text gap, inline padding inside pills |
| sm  | 8px  | Compact stack gap, button inner padding |
| md  | 16px | Default body stack gap, screen inline padding (mobile), card inner padding |
| lg  | 24px | Hero element stack gap (visual → H1 → sub → CTA), section inner padding |
| xl  | 32px | Section top/bottom padding (mobile), between major blocks |
| 2xl | 48px | Section top/bottom padding (tablet+), hero vertical breathing room |
| 3xl | 64px | Section top/bottom padding (desktop), full-bleed page margins |

**Breakpoint rules:**
- **Screen inline padding** (`.container` wrapper): `16px` (<640px) → `24px` (640–1024px) → `32px` (≥1024px).
- **Section vertical padding** (top & bottom): `32px` mobile → `48px` sm → `64px` md+.
- **Max content width:** `640px` for text blocks (coming-soon shells, 404), `1200px` for Hero asset band and future sections. Mobile Hero is full-bleed; CTA stack sits in the 16px-inset content lane.

**Exceptions:**
- Primary CTA minimum height **56px** (overrides the 48px that an 8-point scale would suggest) — mandated by HERO-02 success criterion #2.
- Theme-toggle hit target **44×44px** minimum (WCAG tap target) even if visual icon is smaller.
- In-app browser banner height **48px** at mobile (uses `sm × 6`), 56px tablet+.

## Typography

**Scale: 4 sizes (16/18/24/36 at mobile), 2 weights (400 regular, 700 bold).** Hinglish restricted to display/H1 and section-shout micro-copy only; all other text is English.

| Role | Size (mobile 360px) | Size (≥640px) | Weight | Line Height | Letter Spacing | Font Family |
|------|---------------------|---------------|--------|-------------|----------------|-------------|
| **Display / H1** | 36px (2.25rem) | 56px (3.5rem) desktop ≥1024 → 72px (4.5rem) | 700 (bold) | 1.05 | -0.02em | display |
| **Heading / H2** | 24px (1.5rem) | 32px (2rem) | 700 (bold) | 1.15 | -0.01em | display |
| **Body-lg / sub-headline** | 18px (1.125rem) | 20px (1.25rem) | 400 (regular) | 1.45 | normal | body |
| **Body / default** | 16px (1rem) | 16px (1rem) | 400 (regular) | 1.5 | normal | body |
| **Button / CTA** | 16px (1rem) | 16px (1rem) | 700 (bold) | 1 (flush) | +0.04em (UPPERCASE) | display |
| **Caption / banner-sm** (role, not size) | 16px (1rem) | 16px (1rem) | 400 (regular) | 1.4 | normal | body + `color-fg-muted` |

**Weight contract (strict):** Only `400` (regular) and `700` (bold) in Phase 1. No `300`, `500`, `600`, no italics for brand copy. Two weights only — if a visual needs more weight contrast, use `color-fg` vs `color-fg-muted` or the type-scale size gap instead. The 36px→24px→16px size cascade is the primary hierarchy mechanism; weight is secondary.

**Size contract (strict):** Only `16`, `18`, `24`, `36` px at mobile baseline (4 sizes). The 56/72 values are responsive scaling of the Display/H1 role; the 32 value is responsive scaling of the Heading/H2 role. Caption-role text (banner body, 404 sub-copy, nav link labels) renders at `16px` (body size) with `color-fg-muted` plus tighter line-height (`1.4`) to differentiate from paragraph body copy — never a smaller font-size.

**Hero H1 copy (locked, CONTEXT D-05):** `Twist karo. Shake karo. BOOM.`
- Rendered on 360px as 36px / line-height 1.05 / weight 700 / letter-spacing -0.02em.
- `BOOM` set in `color-accent` on light theme (= `brand-deep`, so same color as the rest of H1); on dark theme the `BOOM` word gets `color-accent` (= cream) to keep the three beats visually equal while the word reads as a punch. **Alternative:** underline `BOOM` with a `3px` solid `brand-rose` tap-to-feel underline. **Decision:** underline treatment; keeps three beats legible on both themes. Underline uses `text-decoration-thickness: 3px; text-underline-offset: 4px;`.

**Hero sub-headline copy (locked, CONTEXT D-06):** `Pre-filled flavor caps for any bottle.`
- Body-lg size, `color-fg-muted`, line-height 1.45, max-width `28ch` so it wraps to 2 lines on 360px.

**Button copy case:** All primary/secondary buttons in UPPERCASE (`text-transform: uppercase`) with letter-spacing `+0.04em`. Matches industrial logo adjacency.

**Line-length ceiling for body copy:** `65ch` max. For coming-soon shells and the 404 page the copy is short enough that `max-w-[28rem]` is sufficient.

## Color (60/30/10 split)

| Role | Light-mode hex | Dark-mode hex | Usage |
|------|----------------|---------------|-------|
| Dominant (60%) | `#FFF8EA` brand-cream | `#594545` brand-deep | Page background (`bg-bg`), full-bleed section fills |
| Secondary (30%) | `#FFFFFF` surface + `#9E7676` brand-rose | `#6B5252` surface + `#9E7676` brand-rose | Elevated cards, borders, dividers, muted sub-copy |
| Accent (10%) | `#594545` brand-deep | `#FFF8EA` brand-cream | Primary CTA fill only. See reserved-for list below. |
| Semantic — focus ring | `#594545` light / `#FFF8EA` dark (2px solid, 2px offset) | — | Keyboard focus-visible on every interactive element |
| Semantic — overlay | `rgba(89,69,69,0.72)` light / `rgba(0,0,0,0.72)` dark | — | Banner backdrop (NOT used in Phase 1 — banner is solid); 404 hero scrim if designer picks a photo background |
| Semantic — destructive | **not declared in Phase 1** | — | No destructive actions ship in Phase 1 (no form submits, no deletes). Reserved for Phase 6. |

**Accent reserved for (explicit list — never generic "all interactive elements"):**
1. Primary CTA fill — `<PrimaryCTA>` default state in Hero, coming-soon shells, and 404.
2. Hero H1 word `BOOM` underline (`3px solid brand-rose`, 4px offset).
3. Theme toggle `aria-pressed="true"` state indicator (filled icon vs stroked icon — not a color change).

**Everything else (nav links, text in cards, body, headings, logo background) uses `fg` / `fg-muted` / `bg` / `surface` tokens — NEVER accent.**

**WCAG AA contrast assertions (must pass):**

| Pair | Light-mode ratio | Dark-mode ratio | Minimum | Status |
|------|-----------------|-----------------|---------|--------|

| `accent-fg` on `accent` (CTA label) | `#FFF8EA` on `#594545` = **9.4:1** | `#594545` on `#FFF8EA` = **9.4:1** | 4.5:1 | PASS |

## Component Inventory & Specifications

### 1. `<Nav>` (section — logo-only, theme toggle)

**Position:** Fixed top, `height: 56px` (mobile) / `64px` (≥640px), background `bg` (semi-transparent → solid on scroll — Phase 3 adds the fade-in; Phase 1 renders solid `bg` always).

**Layout (mobile 360px, left to right):**
```
[16px padding] [Logo link] [flex-1 spacer] [ThemeToggle 44×44] [16px padding]
```

**Logo asset:** `/public/logos/logo-horizontal.png` (source: `Media/Logo_SHI-28.png`). Rendered at `height: 28px` (mobile) / `32px` (desktop); width auto. On dark theme, the metallic-black wordmark sits on a `brand-cream` rounded surface (`border-radius: 6px`, inner padding `4px 8px`) — do NOT recolor the logo file (per `capshot-brand`).

**No hamburger. No menu. No in-nav links.** Logo-only is a CONTEXT D-16 lock.

**Z-index:** `50` (above hero content, below in-app banner at `60`).

**Phase 2 forward-compatibility:** When the hamburger lands in Phase 2, it replaces the right-side theme-toggle slot by moving the toggle inside the hamburger drawer. The `<Nav>` component signature stays stable.

### 2. `<ThemeToggle>` (UI component)

**Icon:** lucide-react `Sun` (light active, 20×20px) and `Moon` (dark active, 20×20px). Icon stroke width `1.75`.

**Hit target:** `44×44px` (WCAG). Icon centered.

**States:**

| State | Visual | aria |
|-------|--------|------|
| Light active (default) | `Sun` icon, stroked (not filled), `color: fg-muted` | `aria-pressed="false"`, `aria-label="Switch to dark mode"` |
| Dark active | `Moon` icon, stroked, `color: fg-muted` | `aria-pressed="true"`, `aria-label="Switch to light mode"` |
| Hover (pointer only, ≥md) | Icon color → `fg` (full) + background `bg: rgba(fg,0.06)` radius `pill` | — |
| Active / press | Scale `0.96` for 120ms, no color change | — |
| Focus-visible | 2px solid `ring` outline, 2px offset, `border-radius: pill` | — |
| Transition | `color 150ms ease`, `background 150ms ease`, `transform 120ms ease` | — |

**Click behavior:** Toggles `.dark` class on `<html>` and persists `localStorage.setItem('capshot-theme', next)`. Also updates `<meta name="theme-color">` by swapping `<meta>` content between `#FFF8EA` and `#594545` so Chrome/Safari browser chrome follows.

**First-load default (CONTEXT discretion):** follows `prefers-color-scheme`. Explicit choice persists in `localStorage.capshot-theme`. The inline FOUC script in `index.html` reads this before React mounts (see FOUC Prevention section below).

**Reduced-motion:** When `prefers-reduced-motion: reduce` matches, `transform` and `background` transitions skip; color still swaps.

### 3. `<PrimaryCTA>` (UI component, cva-driven)

**Reads from `src/config/cta.ts`:** label + href + kind + trackingId + ariaLabel. Component takes `slot: 'primary' | 'nav'` prop (defaults to `'primary'`). All Phase 1 renders use the default slot; the `'nav'` slot exists for Phase 2+ forward-compat.

**Variants (cva):**

| Variant | Padding | Height | Width | Case |
|---------|---------|--------|-------|------|
| `size: lg` (default — Hero) | `px: 24px, py: 16px` | **56px** (locked by HERO-02) | `width: 100%` on mobile, `auto` on ≥sm (then min-width 240px) | UPPERCASE |
| `size: md` (coming-soon shells, 404) | `px: 20px, py: 12px` | 48px | `auto`, min-width 200px | UPPERCASE |

**Base style (both variants):**
- Font: display, weight 700, size 16px, letter-spacing +0.04em.
- Border radius: `pill` (`9999px`).
- Background: `color-accent` (= `brand-deep` light / `brand-cream` dark).
- Text color: `color-accent-fg` (= `brand-cream` light / `brand-deep` dark).
- Shadow: `--shadow-cta`.
- Icon slot after label: optional `<ArrowUpRight>` (lucide, 16px, stroke 2) for `kind: 'whatsapp'` and `kind: 'shopify'` — Phase 1 renders the arrow because every CTA opens in a new tab.
- `target="_blank"` and `rel="noopener noreferrer"` for external destinations (WhatsApp, future Shopify).
- `data-cta={trackingId}` attribute for Meta Pixel event binding.

**States:**

| State | Visual | Duration |
|-------|--------|----------|
| Default | Fill `color-accent`, text `color-accent-fg`, shadow `--shadow-cta` | — |
| Hover (≥md pointer) | Background darkens 8% (`color-mix(in oklab, color-accent 92%, black)`) — on light this reads as near-black; on dark it reads as warm off-cream | 150ms |
| Active / press | `transform: scale(0.98)`; shadow collapses to `0 1px 2px rgba(89,69,69,0.18)` | 120ms |
| Focus-visible | Default style + `outline: 2px solid var(--color-ring); outline-offset: 3px` | — |
| Disabled | **Not applicable in Phase 1** — the CTA is always available because its destination is a `wa.me` deep-link that always resolves. The disabled state is reserved for Phase 6 (out-of-stock bundles). If a developer sets `disabled`, visual = opacity 0.5 + `cursor: not-allowed` + aria-disabled, no pointer events. |
| Loading | **Not applicable in Phase 1** — the CTA is an `<a>` tag, no async state. Reserved for Phase 6 cart-add. |

**Pixel + CAPI firing (CONV-01):**
- On `click`, before navigating (anchor click default), fire:
  1. Client-side: `fbq('track', 'Lead', { event_id })` with `event_id = crypto.randomUUID()`.
  2. Server-side: `fetch('/api/track-lead', { method: 'POST', body: JSON.stringify({ event_id, event_source_url, user_data }) })` — fire-and-forget (do NOT `await`; must not block anchor navigation).
- The `event_id` is attached to both calls → deduplicates in Meta Events Manager.
- CAPI endpoint lives at `/api/track-lead` (Vercel Edge Function or Netlify Edge Function, matching hosting choice).

**Reduced-motion contract:** All CTA state transitions respect `prefers-reduced-motion: reduce` — `transform` and `box-shadow` transitions skip (instantaneous); color changes still apply.

### 4. `<Hero>` (section — route `/` only)

**Viewport sizing:** `min-height: 100dvh` with `100vh` fallback. Fallback order in CSS:
```css
.hero {
  min-height: 100vh;                     /* fallback */
  min-height: 100dvh;                    /* modern iOS Safari + Chrome Android */
}
```
Uses `min-height` (not `height`) so landscape rotation and content growth don't crop. **Must verify on a real iPhone (not DevTools emulation).** HERO-01 success criterion #2 requires the CTA button to be visible above the Safari dynamic toolbar on first paint at 360×640.

**Safe-area padding:** Top padding adds `env(safe-area-inset-top)`; bottom padding adds `env(safe-area-inset-bottom) + 16px`. `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` enables this in `index.html`.

**Mobile layout (360×640 baseline, nav 56px subtracted):**
```
┌─────────────────────────────────────────┐  ← safe-area-inset-top
│ [Nav 56px — fixed]                      │
├─────────────────────────────────────────┤
│                                         │  ← space-xl (32px) breathing room
│                                         │
```

### 5. `<InAppBrowserBanner>` (UI component — sticky top)

**Position:** `position: sticky; top: 0; z-index: 60` — sits ABOVE the fixed Nav (nav z-index 50). Pushes nav + hero down by banner height when visible (CONTEXT D-10).

**Visibility logic:**
- Component mounts in `App.tsx` (above `<BrowserRouter>` so it persists across route changes).
- On first render, calls `isInAppBrowser()` from `src/lib/detectInAppBrowser.ts`:
  - Returns `'instagram' | 'facebook' | null` (UA match for `/Instagram/i` and `/FBAN|FBAV/i`).
  - If `null` → component renders nothing.
  - If `'instagram' | 'facebook'` AND `sessionStorage.getItem('capshot-inapp-dismissed') !== '1'` → render.
- Android branch: on mount, if UA matches Android AND in-app, `window.location.href = 'intent://capshot.co#Intent;scheme=https;package=com.android.chrome;end'`. The banner itself still renders as a visible fallback in case the intent handoff fails (CONTEXT D-13).

**Visual (mobile, decision — resolved default):**

**Full-width solid bar** (not floating pill). Reason: a floating pill competes with the Hero CTA for the user's eye; a full-width bar reads as system chrome and is easier to dismiss by thumb. Height 48px mobile / 56px ≥sm.

```
┌─────────────────────────────────────────────────────┐
│ For the best experience, open in Safari →      [×] │  ← 48px height
└─────────────────────────────────────────────────────┘
```

- Background: `color-fg` (= `brand-deep` light / `brand-cream` dark) — inverted from page, reads as a system alert.
- Text color: `color-bg` (= inverse — `brand-cream` light / `brand-deep` dark).
- Font: body, 16px (body-size — never a smaller type scale per Size contract), weight 400, line-height 1.4, `color-bg` (inverted on `color-fg` surface).
- Right-arrow glyph `→` is literal Unicode `→`, kerned with 4px left margin from the preceding word. Signals "action required" per CONTEXT D-12.

## FOUC Prevention (dark-mode inline script)

**Inline this blocking script in `<head>` of `index.html`, BEFORE any Vite-injected `<script>` tags:**

```html
<script>
  (function () {
    try {
      var saved = localStorage.getItem('capshot-theme');
      var systemDark = window.matchMedia && window.matchMedia('(prefers-color-scheme: dark)').matches;
      var isDark = saved === 'dark' || (!saved && systemDark);
      if (isDark) document.documentElement.classList.add('dark');
      // Sync meta theme-color so Chrome/Safari address bar matches
      var meta = document.querySelector('meta[name="theme-color"]');
      if (meta) meta.setAttribute('content', isDark ? '#594545' : '#FFF8EA');
    } catch (e) {}
  })();
</script>
```

**Rules:**
1. Script runs synchronously before `<body>` parse; `.dark` class is on `<html>` before CSS resolves → zero cream-to-dark flash on cold-cache loads (CONV-04 success criterion).
2. `<html>` and `<body>` background colors are set explicitly in CSS at the top of the cascade so the earliest paint also matches: `html { background: var(--color-bg); color: var(--color-fg); }`.
3. `<meta name="color-scheme" content="light dark">` in `<head>` so scrollbars and native form controls follow.
4. `<meta name="theme-color" content="#FFF8EA">` (default; script above swaps to `#594545` on dark detect).

**Lighthouse assertion:** No CLS attributable to theme flip. Verify via Chrome DevTools Performance panel on cold-cache simulated 4G.

## Interaction Contracts

### Focus states

- Every `<a>`, `<button>`, and interactive icon has `:focus-visible` with: `outline: 2px solid var(--color-ring); outline-offset: 3px; border-radius` matches the element.
- Default browser focus ring is suppressed with `:focus:not(:focus-visible) { outline: none }` (keyboard-only focus is preserved).
- Primary CTA focus-visible is extra prominent: outline offset 3px with 2px solid `--color-ring` AND the base shadow — compounding, not replacing.

### Hit targets (minimum)

| Element | Minimum size |
|---------|--------------|
| Primary CTA | **56×240px** (56px tall per HERO-02; 240px min-width desktop, 100% width mobile) |
| Theme toggle | **44×44px** |

| Nav logo link | **44×44px minimum** hit area (visual logo may be smaller) |
| 404 "Back to home" link | **44px tall** hit area |

### Keyboard navigation order

Tab order for `/` (Hero route):

1. Skip-to-main-content link (visually hidden until focus) → anchors to `<main id="main">`
2. Nav logo link (home)
3. ThemeToggle
4. In-app banner dismiss (only if banner visible)
5. Primary CTA

Tab order for coming-soon routes: same, with Primary CTA at the end. 404: same + "Back to home" link after CTA.

**No focus traps.** No modals in Phase 1. Banner is dismissible via keyboard (Enter/Space on dismiss) but doesn't trap focus.

### Reduced motion

`@media (prefers-reduced-motion: reduce)`:
- All `transition` properties on `<PrimaryCTA>` and `<ThemeToggle>` collapse to `0ms`.

- Phase 3 Motion choreography must honor the same contract (CONV-05 + Phase 3 success criterion #3).

### Screen reader behavior

- `<main>` landmark wraps page content; `<nav>` landmark on Nav; `<footer>` deferred (no footer in Phase 1).
- H1 is the only `<h1>` per route.
- WhatsApp CTA announced as "Try CAPSHOT, link, opens in a new tab" via `aria-label` + `target="_blank"` + semantic `<a>`.
- Theme toggle announced as "Switch to dark mode, button, pressed: false" (changes to `pressed: true` after toggle).
- In-app banner is a `<div role="status" aria-live="polite">` so SR users hear the recommendation; dismiss button is `<button type="button" aria-label="Dismiss browser recommendation">`.
