**Files modified:** `src/sections/CatalogBundles.tsx`
**Commit:** `efa32f4`

scaffolds from `text-[color:var(--color-brand-rose)]` to
`text-[color:var(--color-fg)]` (preferred option 1 from the review).

deep (both are brand palette tokens; the brand-rose accent is still
carried by the adjacent numbered pill). Dark mode goes from
near-invisible to the correct high-contrast token pair.

### WR-02: UspComparison asterisk footnote has no programmatic association with the "₹24-₹30 per cap*" cell

**Files modified:** `src/sections/UspComparison.tsx`, `tests/e2e/usp-comparison.spec.ts`
**Commit:** `0736746`
**Applied fix:**

1. Added `id="price-pending-note"` to the footnote `<p>`.
2. Added `aria-describedby="price-pending-note"` to the capshot `<td>`
   on the pending-price row, gated behind the same
   `isPricingPending` discriminator that drives the row's existing
   `data-pricing-pending` attribute. The gating ensures future rows
   that don't carry the pending flag remain unaffected.
3. Hardened the pending-state check (IN-01 opportunistic, same hunk):
   `'pricingPending' in row` was a key-presence-only check that would
   mis-flag a future row with `pricingPending: false`. Replaced with
   `'pricingPending' in row && row.pricingPending === true` so the
   runtime guard honors the `as const` type intent on the ROWS
   tuple.
4. Added e2e regression guard `UC10` in `tests/e2e/usp-comparison.spec.ts`
   asserting both the `<td aria-describedby="price-pending-note">` and
   the matching `<p id="price-pending-note">` exist exactly once each.
   Unresolved `aria-describedby` pointers are silently dropped by AT
   engines, so the test locks both halves — the a11y wiring is only
   effective when both exist.

Followed the user's explicit id-naming override (`price-pending-note`,
not the review's suggested `usp-pricing-footnote`).

**Verification:**

- Tier 1: re-read of lines 130-205; both id and aria-describedby
  present; the gating condition in the map callback is the new
  `isPricingPending` guard.
- Tier 2: `tsc --noEmit` clean; `scripts/ci-grep-forbidden-strings.mjs`
  clean; `vitest run` 76/76 (no unit tests touch USP ids but confirms
  no regression).
- Full e2e: the new UC10 passes; UC1-UC9 + UC-RM-1 all continue to
  pass; UC2 row order unchanged; UC8 data-pricing-pending attribute
