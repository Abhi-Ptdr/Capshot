## Fixed Issues

### CR-01: `getCta` silently returns `undefined` for unknown dotted slots

**Files modified:** `src/config/cta.ts`
**Commit:** `25f9328`
**Applied fix:** Replaced the `slot as 'primary' | 'secondary' | 'nav'` type-assertion fallthrough with an explicit `switch` over every `CtaSlot` literal plus a `never`-typed exhaustiveness check in the `default` branch. TypeScript now fails at compile time if a new slot is added without a case; a stray `string` escaping the type boundary throws a visible error instead of returning `{ href: undefined, ... }`.

### WR-01: `&tier=` query param is dead code for its stated purpose

**Files modified:** `src/config/cta.ts`, `tests/unit/cta.spec.ts`, `tests/e2e/catalog-bundles.spec.ts`
**Commit:** `03147a5`
**Applied fix:** Moved tier attribution from the dropped `&tier={tier}` query parameter into the URL-encoded `text` body (`Interested%20in%3A%20{tier}`). The wa.me URL spec propagates ONLY `text` into the WhatsApp client, so the Business inbox now actually sees the tier string in every inbound lead. Module header comment, three per-tier URL constants, three unit-spec assertions, and the CB4 e2e assertion were updated in lockstep so every grep gate still sees per-tier literals.

### WR-02: TrustBadge discriminated union is leaky via the default `variant` arm

Added a new `@ts-expect-error` test asserting that omitting `variant` is now a compile error, locking the WR-02 contract.

### WR-03: `getCta('secondary')` had `kind: 'external'` but `href: '/flavors'`

### WR-05: TB5 2×2-wrap test was layout-dependent and brittle (and 2×2 was wrong)

**Files modified:** `tests/e2e/trust-badges.spec.ts`
**Commits:** `f52a106`, `165077e` (correction)
**Applied fix:** Initial commit applied the review's suggested strict-2×2 assertion. A real-browser Playwright probe revealed the actual layout at 360×640 is `1 + 1 + 2` (FSSAI alone / Plant-based ingredients alone / Made in India + Secure Checkout together) because "Plant-based ingredients" at ~215px cannot pair with any sibling under 360px of container width — the review's 2×2 estimate was wrong. The correction commit rewrites TB5 to bucket all four items by `y` with ~1px tolerance and demand at least 2 DISTINCT rows plus the last row sitting meaningfully below the first. This catches the regression the review cared about ("4 items don't wrap at narrow mobile") without over-specifying a layout the component never produces.
