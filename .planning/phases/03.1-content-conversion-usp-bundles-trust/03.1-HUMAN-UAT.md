# Phase 03.1 — Human UAT

The automated verification is 4/4 PASS. The remaining gate is a single consolidated real-device smoke test harvested verbatim from Plan 04 Task 3's `<human-check>` block. Nothing else blocks phase close.

## UAT-01: Real-device smoke test — Phase 3.1 sections

### Setup

Boot `npm run dev` on the local machine. Open http://localhost:5173/ in Chrome DevTools with device toolbar set to **Pixel 7 (390×844)** OR **iPhone 12/13 (390×844)**. Optionally mirror on a real Android Chrome AND a real iOS Safari via the local network URL.

### Scroll walkthrough (top → bottom)

1. **Hero** — Phase 1 regression check only.
2. **HowItWorks** — Phase 2+3 regression check only.
3. **USP Comparison** — 3 rows (Freshness / Nutrient Value / Portability), icons left of each row, "Store-bought bottled drinks" vs "CAPSHOT (SHI-28)" column headers, right-column text bold + brand-rose, no horizontal scroll on 360×640.
4. **Catalog & Bundles** — one shared H2, flavor horizontal scroll works byte-identical (swipe through 8 flavors + "See all 16 flavors →" tile links to `/flavors`), below flavors 3 bundle cards (Trial / Fitness / Bulk) stacked on mobile, Fitness card has visible "Best Value / Most Popular" badge, each card has 05/15/30 cap-count badge in brand-rose.
5. **Each bundle CTA** — tap "Join waitlist for early access" and confirm the WhatsApp URL carries `&tier=trial|fitness|bulk` (inspect anchor href in DevTools before tapping if easier).
6. **Trust Badges strip** — 4 badges in order (FSSAI Licensed / Plant-based ingredients / Made in India / Secure Checkout), no yellow dev-warning banner, badges are not clickable links (visual-only), on <375px viewport the strip wraps to 2×2.

### Reduced motion

7. DevTools → Rendering → Emulate `prefers-reduced-motion: reduce`. Reload `/`. All three new section entrances should snap into final state immediately (no fade/slide); FlavorTeaser scroll-snap still works.

### Dark mode

8. Toggle dark mode via Nav theme toggle. All three new sections render legibly in dark (palette tokens follow Phase 1 locks: `#594545` / `#815B5B` / `#9E7676` / `#FFF8EA`).

### Expected

- All three Phase 3.1 sections render in the locked order between Hero/HowItWorks and the footer slot (empty in Phase 3.1).
- Entrance animations fire once per section as scrolled into view (fade+slide ~0.6s).
- Bundle CTAs open WhatsApp with the pre-filled "Hi! Add me to the CAPSHOT waitlist." message AND the `&tier=` query is in the URL.
- Trust strip renders 4 visual-only badges in locked order; no `<a>` wrappers, no dev warning banner, wraps to 2×2 on narrow mobile.
- Reduced-motion suppresses all three section entrances to final state immediately.
- Dark mode renders all three sections with WCAG-adequate contrast.

### Why human (not Playwright)

Playwright asserts DOM contracts (opacity, text, class names, href patterns) but cannot grade perceived animation smoothness, color legibility against the hero image, mobile tap-ergonomics on real-device multi-touch, or WhatsApp handoff behavior from the real native app.
