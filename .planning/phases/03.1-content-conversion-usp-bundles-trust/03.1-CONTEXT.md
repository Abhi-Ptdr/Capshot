## Implementation Decisions

### Section 3: USP & Comparison Grid

- **D3.1-01:** USP comparison left-column (competitor) label = **"Store-bought bottled drinks"**. Blueprint's "Regular Energy Drinks" label was CI-blocked by Phase 1's `/energy\s+drink/i` grep gate (INFRA-06). "Store-bought bottled drinks" is the broadest honest framing — covers canned juices + flavored waters + sports drinks + energy drinks simultaneously, which matches CAPSHOT's "refreshing hydration, NOT energy drinks" positioning constraint (PROJECT.md).
- **D3.1-02:** USP visual format = **classic 3-row × 2-col semantic `<table>` with lucide-react icons prefixing each row**. Row icons: `Clock` (Freshness) · `Leaf` (Nutrient Value) · `Package` (Portability). Left column styled with `--color-fg-muted`; right column (CAPSHOT) uses `--color-brand-rose` accent + bold text. Reduced-motion default (static table). SEO-friendly semantic HTML. Minimal Motion footprint — one section-fade entrance only, Claude's discretion on exact Motion params (follow the Phase 3 `whileInView` + `motion-reduce:` pattern).
- **D3.1-02a:** Locked row copy (adapted from blueprint for the "store-bought bottled drinks" framing):
  - Freshness · Store-bought: "Preserved on shelves for months" · CAPSHOT: "Activated instantly by you"
  - Nutrient Value · Store-bought: "Degrades over time in bottles" · CAPSHOT: "100% intact, sealed vitamins"
  - Portability · Store-bought: "Heavy to carry around" · CAPSHOT: "Pocket-sized, travel-friendly cap"

### Section 4: Product Catalog & Pricing Bundles

- **D3.1-03:** Bundle pricing display = **real ₹ prices on every bundle card** (user chose "lock Phase 6 pricing today"). Locked numbers:
  - Trial Pack (5 caps): **₹120** (≈₹24/cap)
  - Fitness Pack (15 caps + 1 Free Smart Shaker Bottle): **₹349** (≈₹23/cap incl shaker; "Best Value / Most Popular" badge)

FlavorTeaser's own JSX, CSS scroll-snap behavior, chevron state, useRef, scroll handlers, 8-flavor curated enumeration, 9th "See all 16 flavors →" terminal tile, Phase 3 `<m.section>` entrance wrapper, and all Phase 2 FT1–FT6 + Phase 3 FT-P3-1/FT-P3-2 e2e assertions MUST remain byte-identical. ### Section 5: Trust Badges strip

- **D3.1-07:** Trust badges = **4 badges, visual-only** (static icon + text, no `<a>` wrapper, no evidenceUrl requirement). User explicitly chose: "Just use the static badge icon and with text for eg 'FSSAI Licensed'. We can always map it to the url and licence no. when we have those details."
- **D3.1-07a:** Locked badge labels (unchanged from Phase 1 TrustBadge primitive's strict union type):
  - **FSSAI Licensed** · icon: lucide-react `ShieldCheck`
  - **Plant-based ingredients** · icon: lucide-react `Leaf`
  - **Made in India** · icon: lucide-react `MapPin` (Claude's discretion to swap to `Flag` if visually better)
  - **Secure Checkout** · icon: lucide-react `Lock`
- **D3.1-08:** TrustBadge primitive extension = **add `variant: 'visual-only' | 'linked'` prop to the existing `src/components/ui/TrustBadge.tsx`**. Default stays `'linked'` to preserve the Phase 1 contract. `variant='visual-only'` renders static icon + label with no `<a>` wrapper, does NOT require evidenceUrl, does NOT throw in PROD, does NOT emit the `data-pending-fssai` dev warning. TypeScript enforces the two shapes via discriminated union (visual-only variant omits evidenceUrl from its props type; linked variant keeps it required). Phase 5 migrates each badge from `visual-only` → `linked` as evidence arrives (when GATE-FSSAI resolves, FSSAI gets a real evidenceUrl + 14-digit number; other three badges get internal `/about#...` or external evidence anchors).
- **D3.1-09:** Trust strip position = **immediately above the `<footer>`** (blueprint-correct "prominently near the footer" placement). Classic trailing-certification pattern; does not interrupt the USP → Catalog+Bundles conversion funnel. If no `<Footer>` component ships yet in Phase 3.1, trust strip sits as the LAST homepage section inside `<main>`.
- **D3.1-10:** Trust strip visual layout = **4-badge horizontal row that wraps to 2×2 on narrow mobile (<375 px)**. On ≥375 px mobile and up, all 4 badges fit on one row. Use `flex flex-wrap justify-center gap-3` or `grid grid-cols-2 sm:grid-cols-4`. Each badge is `inline-flex items-center gap-2 rounded-full border border-[color:var(--color-border)] bg-[color:var(--color-surface)] px-3 py-2 text-sm text-[color:var(--color-fg)]` — matches the existing Phase 1 TrustBadge linked-variant styling for visual consistency with future Phase 5 linked badges.

Within-section elements (table rows, bundle cards, trust badges) do NOT individually stagger — section-level only, matching Phase 3's FlavorTeaser treatment (D3-11).
