## Phase 3.1 contract subtleties encountered

1. **`>Feature<` single-line requirement.** JSX by prettier default renders a short-text `<th>` across 3 lines (opening tag / text / closing tag). `grep -c '>Feature<'` returns 0 against the multiline form. The plan's acceptance criterion of `= 1` forced the inline single-line form, protected by `// prettier-ignore`. Same pattern will apply to any future `>text<` grep assertion on JSX.

2. **Optional discriminator on `as const` tuple.** The ROWS tuple widens each entry's inferred shape only insofar as `as const` allows — adding `pricingPending: true as const` to one entry forks the tuple's union type cleanly. Attribute spread `{ 'data-pricing-pending': 'true' as const }` requires the string literal (DOM attributes must serialize to strings), hence `'true'` not `true`.

3. **Attribute spread for conditional DOM attrs.** Writing `<tr data-pricing-pending={pricingPending ? 'true' : undefined}>` emits `data-pricing-pending=""` (truthy coercion of `undefined`) in some React versions. The spread form `{...pricingProps}` where `pricingProps` is either `{}` or `{ 'data-pricing-pending': 'true' }` guarantees the attribute is EITHER present with value `'true'` OR entirely absent from the DOM — this is what the `tbody tr[data-pricing-pending="true"]` Playwright selector requires.

4. **Asterisk footnote positioned OUTSIDE `<table>` (not `<caption>` or `<tfoot>`).** A `<caption>` would be announced by screen readers as the table's title BEFORE row/column headers — the pricing-pending disclaimer isn't the table's accessible-name content. `<tfoot>` is semantically for data footers (totals / summaries), which this isn't either. A plain sibling `<p>` renders byte-identically and keeps the table a11y tree clean.

5. **Grep-count discipline on docstring expansions.** The 5-row USP docstring must mention the two new row concepts without using the literal dim strings more than once each — otherwise `grep -c 'Taste variety' = 2` fails the acceptance gate. Phrasing shifted to abstract references ("taste-variety and per-drink price", "two new user-selected rows", "per-drink price row").
