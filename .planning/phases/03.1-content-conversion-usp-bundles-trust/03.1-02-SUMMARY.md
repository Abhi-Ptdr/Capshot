## Phase 3.1 contract subtleties encountered

1. **Comment-vs-value grep discipline.** The CLAUDE.md project rule "Comments must stay grep-safe" (Phase 1 Plan 02 execution note in STATE.md) applies to any `grep -c "..." = 1` acceptance criterion. Any locked literal string in a comment adds to the grep count. Strategy: paraphrase in file-header comments without using the banned literal phrase. Applied to all 5 affected grep patterns in Task 2's acceptance list.

2. **Playwright `getByRole('table').first()` vs region role.** `tests/e2e/flavor-teaser.spec.ts` uses `getByRole('region', { name: 'Flavor teaser' })` because the scroll-snap region carries an explicit `aria-label`. The USP table has no such wrapping region — the `<table>` IS the semantic landmark. `page.getByRole('table').first()` is the equivalent surface, and `.first()` is defensive against a future phase (CatalogBundles in Plan 03) adding a sibling table on `/`.

3. **`test.use({ reducedMotion: 'reduce' })` placement.** Must be in a nested describe (not file-level). The reason: file-level `test.use(...devices['Pixel 7'])` already sets the device-emulation profile; combining a second file-level `test.use({ reducedMotion: ... })` is safe in Playwright 1.64, but the Phase 2 convention (comment at `tests/e2e/flavor-teaser.spec.ts:144-147`) is to scope the fixture to the describe that needs it so main-describe tests don't accidentally inherit it. This matches the Phase 3 pattern established by FT-P3-2 at `flavor-teaser.spec.ts:149-164`.

4. **Comment duplicates of `test.use({ ...devices['Pixel 7'] })` are tolerated.** The acceptance criterion for this grep says `≥ 1`, not `= 1`, so the doc-reference comment at line 29-30 of the spec file (describing the Phase 2 convention) is fine. Only the strict `= 1` criteria needed comment-rephrasing.
