### "Best Value / Most Popular" badge visual style

**Chosen style: absolutely-positioned corner PILL overhanging the card top edge.**

```
<span className="absolute -top-3 right-6 rounded-full
                 bg-[color:var(--color-brand-rose)]
                 px-3 py-1 text-[11px] font-bold tracking-wider
                 text-[color:var(--color-brand-cream)] uppercase
                 shadow-[0_4px_12px_-2px_rgba(89,69,69,0.3)]">
  Best Value / Most Popular
</span>
```

Rationale (per D3.1 Claude's Discretion item 3 — mobile 360×640 readability is the gate):
- The pill overhangs the card by 12px (`-top-3`) so it reads as a sticker on the Fitness card, not a label inside it.
- Positioned `right-6` (24px from right edge) so it sits past the price/includes column but doesn't collide with the H4 title which has room to breathe at the left.
- Uppercase 11px text matches the Phase 2 FlavorCard range chip typography — same visual language, different accent.
- Confirmed via Playwright CB5 (`toContainText('Best Value / Most Popular')` on `[data-bundle="fitness"]`) that the pill is visible inside the Fitness card at Pixel 7 viewport.
- Companion treatment: Fitness card also gets `md:scale-[1.03] md:shadow-[0_10px_30px_-6px_...] ring-[color:var(--color-brand-rose)]/40` on md+ to pull the eye at desktop — on mobile where the cards stack, the pill is sufficient prominence without the scale (which would clip against siblings).

## Phase 3.1 contract subtleties encountered

1. **Plain `<section aria-labelledby>` vs `<Section>` primitive — Pitfall 5 in practice.** Initial impulse was to use `<Section>` from `src/components/primitives/Section.tsx` for the CatalogBundles root (it IS semantically a section after all), but the Phase 1 primitive includes `py-8 sm:py-12 md:py-16` which would stack on top of FlavorTeaser's own Phase 1 `<Section>` from `src/sections/FlavorTeaser.tsx:116`. The PATTERNS Pitfall 5 explicitly spells this out — the fix is a plain `<section>` with just the aria-labelledby relationship. Acceptance criterion `grep -c 'import Section' src/sections/CatalogBundles.tsx = 0` enforces the pattern at the import level.

2. **Template-literal `${tier}` evades literal grep — unroll the loop.** The CB4 acceptance criterion is `grep -c "&tier=trial\|&tier=fitness\|&tier=bulk" tests/e2e/catalog-bundles.spec.ts ≥ 3`. A `for (const tier of [...] as const) { expect(href).toContain(\`&tier=${tier}\`) }` loop asserts the behavior at runtime BUT the source string the grep sees is `&tier=${tier}` (3 chars + interpolation), not the literal `&tier=trial`. Unrolling the loop into 3 explicit assertion blocks is the correct fix because it (a) satisfies the gate and (b) makes the per-tier intent self-documenting at a glance when a future author reads the spec. The underlying intent — "catch the Pitfall 4 regression where a dev writes `?tier=` instead of `&tier=`" — is preserved exactly.

3. **CB6 "≥2 motion wrappers" vs an exact count.** The CatalogBundles heading band is one `<m.section>`; the Bundles tri-card lane is a second; the FlavorTeaser's existing `<m.section>` is a third; the UspComparison's is a fourth. CB6's `expect(count).toBeGreaterThanOrEqual(2)` leaves headroom for Plan 04 to add a 5th (TrustBadges) without requiring an edit to this spec — defense-in-depth against test-brittleness as the composition grows. The reduced-motion CB-RM-1 variant uses `.first()` for the same reason.

4. **Comment-vs-value grep discipline carried forward from Plan 01/02.** The CLAUDE.md project rule "Comments must stay grep-safe" (Phase 1 Plan 02 decision in STATE.md line 89) applies to any `grep -c "..." = 1` acceptance criterion. For this plan the affected literals were `Best Value / Most Popular` (acceptance = 1) and `CB-RM-1` (acceptance = 1). Both had their docstring/comment references paraphrased so the single on-source occurrence lives at the runtime assertion / test name respectively.
